# Objects tab

<Art name="cube-grass" size={105} />

The Objects tab lists every object in the scene you are editing, and is where you add new ones.

<Side shot="objects-tab-empty-scene">

<Legend items={[
  <><b>Scene</b> — the scene you are editing. Tap to switch or add scenes (see <a href="./scenes">Scenes</a>).</>,
  <><b>◫ Types</b> — switch the list to object types (see <a href="#types">Types</a>).</>,
  <><b>＋ Add</b> — add an object.</>,
  <><b>Object rows</b> — tap to select. Children are indented under their parent.</>,
]} />

A new project has a **Camera**, a **Sun** light and a **Ground**.

</Side>

## Object rows

Each row has an icon showing what the object is (🎥 camera, 💡 light, 🧊 shape or model, 🖼 UI, 🔤 text, ✨ particles, 🔊 sound, ○ empty).

<Row>
  <Crop name="objects-selected-row" caption="Selected row: tap Edit › to open the Inspector" width={320} />
  <Crop name="objects-hidden-row" caption="👁 hides an object in the editor and the game" width={320} />
</Row>

- **Tap** a row to select it; tap the selected row again (or **Edit ›**) to open the [Inspector](./inspector).
- **👁** hides or shows the object. Hidden objects are not drawn in the game either, but still exist — events can show them again.
- **⋮** opens the object menu.
- A **▾ / ▸** arrow before a parent folds or unfolds its children.
- **Drag a row** to reorganize: drop it onto the **middle** of another row to make it that object's child, onto a row's **top or bottom edge** to move it before or after, or onto the **empty space below the list** to bring it back to the top level. With a mouse, just drag; on a phone, **press and hold** a row a moment, then drag (a quick swipe still scrolls). It stays where it is in the 3D world. On-screen UI and 3D objects can't be mixed.
- Greyed-out rows are **inactive** objects (see the Inspector’s *Active* switch).

## Types {/* #types */}

Objects that share a name are one **object type**: events and scripts address them together. Press **◫** at the top of the tab to list the types instead of the scene's tree, one row per name:

- **This scene's types**, with how many instances the scene has.
- **🌐 Global** — objects with **Keep across scenes** on in **another scene** (see [Scenes](./scenes#keep-an-object-across-scenes)). They come along into this scene while the game runs.
- **📦 Prefabs** that this scene has no copy of.

**Tap** a type to select all of its instances in the scene. **Drag** a type into the 3D view (on a phone, press and hold first) or press **＋** to place a copy: a prefab's copy if there is a prefab of that name, otherwise a copy of one instance with its children, taken from whichever scene has it. UI elements have no ＋, since they live under a canvas. Press **◫** again to go back to the tree.

## Object menu {/* #object-menu */}

<Side shot="object-menu">

Tap **⋮** on a row, or **long-press** the object in the 3D view.

| Item | What it does |
| --- | --- |
| **Edit properties** | Opens the Inspector. |
| **Rename** | Names use letters, numbers and `_` so events can refer to them. |
| **Duplicate** | A copy with the **same name** — an extra instance of the same object type. |
| **Focus in view** | Centers the 3D view on it. |
| **Move up / down** | Reorders the list (also the drawing order of UI). |
| **Set parent…** | Attaches it to another object so they move together. |
| **Unparent** | Detaches it again. |
| **Make prefab** | Saves it (with its children) as a reusable prefab; the object becomes a linked copy of it. |
| **Apply all to prefab** / **Revert all** / **Unpack prefab** | On a linked prefab copy: see [Linked copies](#linked-copies). |
| **Delete** | Deletes it and its children (undo brings them back). |

</Side>

:::tip[Same name = same type]
Objects with the same name are **instances of one object type**. An event about `Coin` works on every coin — see [How events work](../logic/event-sheets). Give *different* things different names.
:::

## Model parts {/* #model-parts */}

An imported 3D model is made of **parts** (meshes, groups and, for animated characters, bones). Under every model object there is a **🧩 Model parts** row; tap it to unfold the model's parts.

| Control | What it does |
| --- | --- |
| **Tap a part** | Selects it. The Inspector then shows a card for the part: **Visible**, **Material** (a material from your project, or *From the model file*), and its **Position, Rotation and Scale**. **↺** puts the part back as the file has it, **×** returns to the object. |
| **👁** | Hides or shows just that part, e.g. a helmet or a weapon on the model. |
| **⋮ → Attach object here…** | Picks another object of the scene and attaches it to the part. It keeps its place in the world, then follows the part. |
| **⋮ → Reset part** | Removes all changes made to that part. |

Only parts you change are saved in the project, so an untouched model costs nothing. A part with its own material is drawn with that material; all other parts keep the model's own.

**Holding things.** Attach a sword to a hand bone and it moves with the animation. The attached row shows a small *→ part name* tag. Its position and rotation are relative to the part, so move it in the Inspector to fit the hand. To detach it, use **Unparent** in the object menu.

:::note
- An attached object **cannot push** the object that holds it: while attached its colliders only detect overlaps (they are *triggers*), so a held shovel never shoves the character around.
- Moving or turning a part that an animation also drives has no visible effect while the animation plays, because the animation sets it every frame. Hide it or give it a material instead.
:::

From a script, `attachTo(parent, "hand_R")` attaches an object to the part with that name, and `detach()` lets go (see the [scripting API](../reference/scripting-api)).

## Prefabs

<Side shot="objects-prefabs">

A **prefab** is a saved object (with its children, components, behaviors and variables) that you can place again and again, and that events can **create while the game runs** (*Create object* action) — bullets, enemies, coins.

- **Make prefab** from the object menu. The object becomes a [linked copy](#linked-copies) of the new prefab.
- Prefabs are kept in the **Files** tab, under the **Prefabs** filter. Tap one and choose **Add to scene**, or drag it into the 3D view to place it where you let go. The same menu **opens** it in [prefab mode](#prefab-mode), renames it, moves it to a folder, or deletes it (copies already placed stay, as plain objects).
- Prefabs also appear in the **＋ Add** menu.
- **Create object** (and `game.spawn("Name")`) also works with a plain object by its name: one placed in the scene, one that only exists in **another scene**, or one **made while playing and destroyed since**. A prefab is still the cleanest way when you want a template that no scene has to contain.

</Side>

### Linked copies {/* #linked-copies */}

A placed prefab stays **linked** to its prefab, like a prefab instance in Unity: change the prefab and every copy in every scene changes with it. In the Objects list a linked copy's name is **blue**, and its top object has the prefab icon.

What you change on one copy is that copy's own (an **override**): its value stays when the prefab changes. Where a copy matches the prefab, it keeps following it. The top object's **position**, **rotation**, **name** and **parent** are always the copy's own and never count as overrides.

Select a copy and the Inspector shows a **prefab bar** at the top:

| Button | What it does |
| --- | --- |
| **📦 Name** | The prefab this object is a copy of. |
| **Open** | Opens the prefab in [prefab mode](#prefab-mode). |
| **Root** | On a child of the copy: selects the copy's top object. |
| **Overrides ▾** | Lists every override of the copy: changed parts, objects added to it, prefab objects removed from it. Pick one to **apply** or **revert** just that, or choose **Apply all** / **Revert all**. Blue when the copy has overrides. |
| **⋮ → Unpack** | Drops the link to this prefab. Prefab copies inside it stay linked to their own prefabs. **Unpack completely** makes everything plain objects. |
| **↳ 📦 Name · Open** | Under the bar, on the top object of a [nested copy](#nested-prefabs) or of a variant's base: that prefab, and **Open** for it. |

A card with an override (Transform, a component, a behavior, the instance variables) gets a **blue bar** on its left and a blue **●** button, and inside it the very fields the copy changed are **bold** with a thin blue edge (a Transform axis, a component field, a behavior setting, Visible / Active / Layer): **Apply to prefab** sends that part to the prefab (and so to every copy), **Revert** takes the prefab's again. A component or behavior added to the copy counts as an override too; reverting it removes it.

- **Apply all** makes the prefab exactly this copy (except where the copy stands). Every other copy takes the change and keeps its own overrides.
- **Revert all** makes the copy the prefab again: its overrides go, objects added to it are removed, removed ones come back.
- The object menu (**⋮** on the row) has **Apply all to prefab**, **Revert all** and **Unpack prefab** for a copy's top object. **Make prefab** on a linked copy applies it too.
- **Duplicate** (and copying a scene) keeps the link. Deleting a prefab unlinks its copies.
- Making a prefab from **another object** with the same name replaces the prefab's contents; copies placed before lose their link.
- A prefab can't hold a copy of itself: placing or applying one that would is refused.
- Copies placed before linked prefabs existed (before v1.0.2's Linked prefabs update) are plain objects. Delete one and place the prefab again to link it.

### Nested prefabs {/* #nested-prefabs */}

A prefab can hold copies of other prefabs: a **Car** with four **Wheel** copies. Put Wheel copies under the car (or place them in Car's [prefab mode](#prefab-mode)), then make or apply the Car prefab: the wheels stay linked to **Wheel**.

- Change **Wheel** and the wheels inside **Car** change, and so does every Car in your scenes.
- A wheel changed inside the Car prefab (or on one Car copy) keeps that change: it is an override, at that level.
- The top object of a nested copy has the prefab icon in the Objects list, and the Inspector shows **↳ 📦 Wheel · Open** under the Car's bar.
- **Make prefab** from a Car copy keeps its wheels as Wheel copies.

### Prefab variants {/* #variants */}

A **variant** is a prefab based on another one, like Unity's Prefab Variant: a **FastEnemy** that is an **Enemy** with more speed. It follows **Enemy** except where it differs.

- In **Files**, tap a prefab → **Create variant** and give it a name. Its card says **Variant of Enemy**.
- Or rename a placed copy and choose **Make prefab** → **Variant of Enemy** (or **Original prefab** for an unlinked new one).
- Open the variant in [prefab mode](#prefab-mode) to change it. Its top object shows the **Enemy** prefab bar: what you change is the variant's own override, and **Apply** sends it up to **Enemy** instead.
- Copies of the variant follow the variant, and so follow **Enemy** too.

### Prefab mode {/* #prefab-mode */}

**Open** (on the prefab bar, or in the prefab's menu in **Files**) opens the prefab on its own, like Unity's prefab mode. The Objects tab shows **‹ Scene name** and **📦 Prefab name** instead of the scene button, and the list holds only the prefab's objects.

Every change you make there goes straight into the prefab, and every linked copy follows as you work (keeping its overrides). Undo works inside prefab mode; back in the scene, one **Undo** takes back the whole visit.

Tap **‹ Scene name** to go back. Pressing **Play**, switching scenes, or opening the Scenes, event sheet, Timeline, Tests or Git panel also takes you back first. Objects you add at the top level in prefab mode (not under the prefab's top object) are not part of the prefab.
