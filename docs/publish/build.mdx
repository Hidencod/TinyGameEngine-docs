# Build

<Art name="flag-small" size={85} />

**☰ → Build** (on a computer **File → Build…**, `Ctrl+Shift+B`) turns your project into a game you can share. Pick a platform, choose the scenes that go in, and tap **Build**.

<Side shot="build-web">

| Part | What it does |
| --- | --- |
| **Web / Android / Windows / Linux** | The platform. Your choice is remembered with the project. |
| **Start scene** | The scene the game opens with. It is the same start scene **Run project** uses. |
| **Scenes in build** | One checkbox per scene. Untick a scene to leave it out of the game, for example a test level. The start scene always goes in. |
| **Settings** | The options of the chosen platform. |

</Side>

account use the Claude models. Every account starts with **50**; they never expire.

- A new game from a starter kit uses about **20 credits**, a small change 1 to 5; the Claude models use more. Each

- Packs: **500** for US$4.99, **1,200** for US$9.99, **3,000** for US$19.99 (in the Android app, Google Play's price

## Web

Makes a game that runs in any browser. **Output** has two choices:

- **Single file (.html)** — one file with everything inside. It plays offline, even from a double-click. See [Web build](./export-html).
- **Folder (.zip)** — a page plus separate files, for web hosts and **itch.io**. See [Web build](./export-html#folder).

## Android

Makes a signed **APK** on your phone, or an **App Bundle** for Google Play, with your own app name, package, version,
icon, orientation and [keystore](./export-apk#signing-key). See [Android build](./export-apk).

## Windows {/* #windows */}

Makes a game that runs in its own window on Windows 10 and 11, with no installer: one **.exe** to share or upload to
**itch.io**, or a **folder** for Steam and other stores. Needs a signed-in account; on Free the game opens with the *Made with* splash, with **Pro** it doesn't.

| Setting | What it does |
| --- | --- |
| **Output** | **Single file (.exe)**: the whole game in one file. **Folder (.zip)**: a folder with `<Game>.exe` and a `data` folder next to it. |
| **Window** | The window's size when the game opens (1280 × 720 unless you pick another). |
| **Fullscreen** | Start fullscreen instead of in a window. |
| **Resizable** | Let players resize the window. The game fits itself as it does in a browser. |
| **App icon** | The icon in Explorer, the title bar and the taskbar. It is the same picture as the Android app icon. |
| **Steam App ID** | Your game's App ID from Steamworks. The build talks to Steam: see [Steam](#steam). Empty = no Steam. |
| **Steam test** | Puts `steam_appid.txt` in the build so you can run it outside Steam while testing. Turn it off for the build you upload. |

- Players switch fullscreen with **F11** or **Alt+Enter**. The **Enter fullscreen** and **Exit fullscreen** actions
  fill the whole screen too.
- A **Quit** button: the **Quit game** action (System), or `game.quit()` in a script, closes the window. In the
  editor it stops the play-test.
- Saves ([save slots](../logic/variables#save-slots), `localStorage`) stay on the player's PC in
  `%APPDATA%\<game name>-<id>`. They survive new versions of the game as long as it is the same project.
- The game runs on **Microsoft Edge WebView2**, which comes with Windows 10 and 11. On the rare PC without it, the game
  says so and links to the download.
- The .exe carries your game's name: Task Manager and the file's **Properties → Details** show it.

### Folder output {/* #windows-folder */}

Unzip it and you get:

```
My Game/
  My Game.exe
  data/          index.html, game.json, assets/…, desktop.json
```

Keep `data` next to the .exe: the .exe runs whatever game is in it. Use the folder for **Steam** (upload the
`My Game` folder as a depot; updates only send the files that changed) and other stores. Antivirus programs also
warn less about it than about the single .exe, which has the game packed onto its end.

### Steam {/* #steam */}

A build with a **Steam App ID** is always a folder. It works with Steam once you add Valve's **steam_api64.dll**:

1. Get the Steamworks SDK from [partner.steamgames.com](https://partner.steamgames.com) (you need a Steamworks
   account and an App ID for your game).
2. Copy `redistributable_bin/win64/steam_api64.dll` from the SDK next to `My Game.exe`.
3. To test, turn on **Steam test**, have Steam open and signed in, and run the .exe. Without the test file, a copy
   started outside Steam closes and Steam starts the game again, as Steam games do.
4. Upload the folder (with the DLL, without `steam_appid.txt`) as your depot.

What reaches Steam:

- **Achievements** and **leaderboards** from [Files → Services](../world/services). Each card has a **Steam ID**: the
  achievement's API name or the leaderboard's name in Steamworks. Empty = the card's **ID**. Achievements unlocked on
  Steam (on another PC) count in the game too. Leaderboard scores are whole numbers: send race times in milliseconds.
- **Stats**: the **Set Steam stat** action, or `game.steam.setStat("kills", 12)`. Steam limits how often a game saves, so stats are sent
  within a minute, achievements within 10 seconds (their pop-up shows then), and everything when the game quits.
- **Rich presence**: what friends see you doing (**Set rich presence**).
- The **overlay**: **Steam overlay is open**, **Open Steam overlay**.
- The player's **Steam name** (`steamname()`), Steam's **language** for the game (`steamlanguage()`), and owned
  **DLC** (**Owns DLC**). The **Steam is running** condition tells a Steam build started from Steam apart from
  everything else; in the editor and on the web it is false and the Steam blocks do nothing.

```js
if (game.steam.available) {
  game.steam.setStat("games_played", (await game.steam.getStat("games_played") ?? 0) + 1);
  game.steam.setRichPresence("status", "Level " + level);
}
```

If a Steam build plays without Steam, `game.steam.error` says why (no DLL next to the .exe, Steam not running or
signed in, an SDK newer than the player's Steam). Show it on a debug screen while you test.

The **Steam overlay** works as in other Steam games: **Shift+Tab** opens it over the game, and achievement pop-ups
show in the corner. Pause the game while it is open: the **Steam overlay is open** condition, or
`game.steam.overlayOpen`. **Open Steam overlay** (or `game.steam.openOverlay("achievements")`) opens it from a button.

### Steam Cloud saves {/* #steam-cloud */}

A game's saves ([save slots](../logic/variables#save-slots), `localStorage`, IndexedDB) stay on one PC unless Steam
copies them. Steam's **Auto-Cloud** does that with no code in the game: in Steamworks, **App Admin → Steam Cloud**, set
a byte and file quota (10 MB and 100 files are plenty), then add these **Root Paths** (`*` as the pattern, with
**Recursive** on). `<save id>` is the folder name the build uses: the game's name and its project ID, as in
`My-Game-k3f9x2a1b7c0`. Run the game once and look in the folder to copy it exactly.

| OS | Root | Subdirectory |
| --- | --- | --- |
| Windows | `WinAppDataRoaming` | `<save id>/EBWebView/Default/Local Storage` |
| Windows | `WinAppDataRoaming` | `<save id>/EBWebView/Default/IndexedDB` |
| Linux | `LinuxXdgConfigHome` | `<save id>/Local Storage` |
| Linux | `LinuxXdgConfigHome` | `<save id>/IndexedDB` |

Copy only these two folders: the rest of the save folder is caches that would fill the quota. Keep the Windows and
Linux paths apart (no root overrides): the two players store saves in slightly different formats. Publish the
Steamworks changes, and Steam downloads the saves when the game starts and uploads them when it quits. The project
ID must stay the same between versions, so keep building from the same project.

### Windows warnings {/* #windows-warnings */}

The .exe is not code-signed, and every build is a new file Windows has not seen before, so players may meet a warning
or two the first time. They are normal for small games shared on itch.io or sent to friends:

| Where | What it says | What to do |
| --- | --- | --- |
| The browser's downloads | *isn't commonly downloaded* | **⋯ → Keep** (Edge: **Keep anyway**) |
| SmartScreen, on opening | *Windows protected your PC* | **More info → Run anyway** |

Uploading the .exe in a **.zip** on itch.io works the same way. If an antivirus reports the game as a threat, it is
mistaking the packed game for something else: tell us at the Help page and we report it to the antivirus maker.

## Linux and Steam Deck {/* #linux */}

Makes a game for 64-bit Linux PCs and the **Steam Deck**: a **folder** in a .zip, no installer. Needs a signed-in
account; on Free the game opens with the *Made with* splash, with **Pro** it doesn't.

The settings are the Windows ones without **Output** (a Linux build is always a folder): **Window**, **Fullscreen**,
**Resizable**, **App icon**, **Steam App ID** and **Steam test**. Pick **1280 × 800** for the Steam Deck's screen.

```
My-Game/
  My-Game        the game: run it (double-click, or ./My-Game in a terminal)
  data/          index.html, game.json, assets/…, desktop.json
  resources/ …   the player's own files
```

- The zip is about **120 MB** whatever the game: the player brings its own browser engine (Chromium, through
  Electron), so the game looks and runs the same on every Linux. The first Linux build downloads the player (it is
  kept for the next builds), so it takes a moment longer.
- Unzip it with a tool that keeps file permissions (the file manager, `unzip`, Steam's depot upload all do). If
  `My-Game` does not start, run `chmod +x My-Game` in the folder.
- Saves stay on the player's PC in `~/.config/<game name>-<id>`, and survive new versions of the game.
- **F11** or **Alt+Enter** switch fullscreen; **Quit game** closes the window.
- The Steam Deck's controls reach the game as a gamepad, as an Xbox controller does on a PC.

### Steam on Linux and the Steam Deck {/* #linux-steam */}

The same as [Steam on Windows](#steam), with Valve's Linux library instead of the DLL:

1. Copy `redistributable_bin/linux64/libsteam_api.so` from the Steamworks SDK next to `My-Game`.
2. In Steamworks, add a **Linux** launch option whose executable is `My-Game`, and upload the folder as a Linux
   depot. The Steam Deck uses the same depot.
3. To test on a Linux PC, turn on **Steam test**, have Steam open and signed in, and run `My-Game`.

Achievements, leaderboards, stats, rich presence, DLC, the player's name and language work as on Windows, and
`game.steam.onSteamDeck` tells the Deck apart. On the Steam Deck the **Steam button** opens the overlay, and
**Open Steam overlay** works too. On a Linux PC the overlay does not open: it cannot take the game's mouse and keys, so a player could not close it. `game.steam.overlayOpen`
stays false. Tested with Steam's Linux runtime (the container the Deck runs games in). If Steam is off,
`game.steam.error` says why (`libsteam_api.so is not next to the game`, Steam not running…). To keep saves on every
PC and the Deck, set up [Steam Cloud](#steam-cloud).

## While it builds

A panel shows the steps (*Player*, *Scripts*, *Files 3 / 19*, *Packing*, …). If your project has [saved tests](../editor/tests), they run first and the build stops if one fails. When it is done, a message shows the size of the game and the file is saved or shared.

## Publish is separate

**☰ → Publish game (link)** puts the game online with a link and does not use the Build panel. See [Publish a link](./publish-link).
