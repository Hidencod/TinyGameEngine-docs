# GitHub

Put a project in a GitHub repository you own, and open it on another device. The editor talks to GitHub directly: there is no server of ours in between, and your sign-in stays in the browser.

The project is stored as small text files (one per scene, event sheet, script and so on), so GitHub can show what changed and two devices rarely touch the same file. See [Backup](./backup#project-as-a-folder-for-git-and-syncing) for the folder layout.

## Sign in

Open the panel with **File → GitHub** (on a phone: **⋮ → GitHub**), or tap the git mark described below.

- **Sign in with GitHub** opens GitHub, asks you to allow the editor, and brings you back. In the app, or when the editor runs on your own computer, it shows a short code instead: press **Open GitHub**, type the code there, and come back.
- If you would rather not sign in, paste a **fine-grained token** (GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens) with **Contents: Read and write** on one repository.

Then pick the **repository** (or make a new one) and the **branch** from the two chips at the top.

On the home screen, **Import from Git** makes a new project from a repository you already have.

## The git mark

The editor shows where the project stands without opening the panel.

- On a **computer** it is a chip in the top bar: the branch name and a number, the files that differ from the last time you synced.
- On a **phone** it is a round button at the bottom right of the viewport. It hides while the game plays.
- A green **↓** means GitHub has a newer commit than the one you last synced.

Tap it to open the panel. The number counts on its own as you edit; the ↓ is checked every few minutes and when you come back to the editor.

## Changes

The **Changes** tab lists two groups:

- **On this device**: what you changed since the last sync, ready to push.
- **On GitHub**: what was changed there, ready to pull.

Tap a file to see what changed inside it, in plain words:

| File | What you see |
| --- | --- |
| Scene or prefab | Objects added or removed, and for a changed object the field: `Camera › transform › position (0, 6, 10) → (1, 2, 3)`. Settings of the scene itself are listed too. |
| Event sheet, material, settings, tables | The fields that changed, and items added or removed from lists. |
| Script or shader | The lines taken out (`−`) and put in (`+`) with their line numbers. |
| Pictures, sounds, models | Added or removed (there is nothing to list inside them). |

The **⋮** beside a file offers **Discard my change**, which puts that file back to what GitHub has. **Discard all** does the same for everything on this device. **Undo last pull** goes back to how the project was before the last pull.

## Pull and Push

- **Pull ↓** brings in what changed on GitHub. When something comes in, the editor opens the project again to show it.
- **Push ↑** sends what changed here as **one commit**. Write a short message first; it is what **History** shows later.

When GitHub has changes, **Pull** is the main button: pull first, then push what is left. **Push** stays off while a file is in conflict. Pulling never sends anything, and pushing never takes anything in.

## When both sides changed the same file

If you and your other device both changed a file, **Pull** merges the two versions by meaning, not by line, the way Unity's Smart Merge does for scenes:

- Changes to **different objects** merge on their own.
- Changes to **different fields of one object** (you moved the Player, they renamed it) merge on their own.
- Objects added on both sides are both kept. An object deleted on one side and untouched on the other is deleted.
- Scripts and shaders merge by line: changes in different places merge on their own.

Only a real clash is a question: the **same field changed to two values**, or something **deleted on one side and changed on the other**. The panel lists each one:

- **Mine** keeps this device's value, **GitHub** takes theirs. **All mine** and **All GitHub** answer all of them at once.
- For code, a clash shows both versions of the lines, and **Both** keeps one after the other.
- Press **Done** when every clash has an answer.

The merged file is kept here and appears under **On this device**. Look at it with the diff, then **Push** to send the merge. Nothing is lost: both older versions stay in GitHub's history.

## History and branches

- **History** lists the commits on the branch, newest first, with who made them and when. Tap one to **Restore** the project to that moment. The way back is **Undo last pull**.
- **Branches** switches branch, makes a new one from the current branch, **merges** another branch into this one, or deletes one. A merge GitHub cannot do (the same lines changed on both) is reported; pull the other branch's changes instead to get the merge screen above.

## What is in the repository

Only the project's own files. Other files in the repository, such as a README or a license, are never touched. The project's **id and dates** are not synced: each device keeps its own.

## Good to know

- The sign-in is kept on the device. **Sign out** (in the **⋮** at the top of the panel) forgets it. Anyone using your browser profile could use it.
- Models and sounds are large: the first push over mobile data can take a while. GitHub refuses a single file above **100 MB**.
- The count in the git mark is worked out on the device from the files, so it can differ for a moment from the panel until the panel checks GitHub.
