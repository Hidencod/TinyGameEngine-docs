# 3D models & animation

<Art name="penguin" size={85} />

Besides the built-in shapes you can use real 3D models: characters, cars, trees, buildings, props.

## Free models library

<Row>
  <Phone name="models-library" caption="Free models" />
  <Phone name="models-library-search" caption="Search: car" />
</Row>

Tap **Objects → ＋ Add → Free models library…** or **Files → 🌐 Free assets**. It shows hundreds of models from [Kenney](https://kenney.nl) kits (characters, platformer pieces, nature, cars, food, furniture…). They are **CC0**: free for any game, even commercial ones, without credit.

- **Search** by name (tree, car, coin…) or filter by kit with the chips.
- Tap a model: **Add to scene**, **Add to assets only**, or **View the kit on kenney.nl**.
- Models are downloaded once and then stored in your project (needs internet the first time).

## Import your own model

Tap **Assets → ⬆ Import** or **＋ Add → Import 3D model…** and pick a **.glb** file (a `.gltf` works only if it’s a single file). **.obj**, **.fbx** and **.stl** files import too (below). Free sources: Kenney, Quaternius, Poly Pizza, Sketchfab (check each model’s licence).

### Other formats

| Format | What to know |
| --- | --- |
| **.glb / .gltf** | The best choice: keeps materials, textures and animations. |
| **.fbx** | Meshes, materials, textures and animations (they show up like a glb's). Models made in centimeters (taller than 50 units) are scaled by 0.01 so they are about the right size in meters. |
| **.obj** | The shape, with the materials and textures of its `.mtl` file when you import them together (below); without it, a plain grey material. Size is taken as it is. |
| **.stl** | A single shape in one grey color (3D-printing files). Models bigger than 20 units are taken to be millimeters and scaled by 0.001; the model is stood up (STL files are usually Z-up), centered, and put on the floor. |

If the size or direction is not what you want, change the object's **Scale** and **Rotation**. The file's kind is read from its content, not its name.

#### Models with textures

Many FBX and OBJ files do not contain their pictures: they only name them (`Leaves.png`, a `.mtl` file). When you import, **select the model and its `.mtl` and picture files together** in the file chooser. They are put into the model, which is stored as a single **.glb**, so the pictures are not added to Files separately. A picture you imported earlier is found by its name too, so importing the textures first works as well.

- If a picture can't be found, a message names it and the model is imported with its own color (soft grey when the file's color is black). It never shows up black.
- Pictures with see-through parts (leaves, fences) are cut out and show both sides.
- Pictures are matched by name, ignoring folders and capital letters (`Leaves.PNG` and `leaves.png` are the same).
- The converted model is a normal glb: you don't need the original files again.

Compressed models work too: **Draco** and **Meshopt** compressed meshes and **KTX2** textures (many downloads from Sketchfab and Poly Haven use them) load like any other, with no setting to change and no internet needed. They are smaller files, so they download and start faster.

:::tip[Model tips for phones]
Keep models low-poly (a few thousand triangles) and textures small (1024 px). Many objects of the same model are cheap; many different high-detail models are not.
:::

## Model settings

Put a model on an object with **Shape & look → Shape: 3D model (file)** and choose the **Model**.

<Crop name="card-mesh-model" width={360} />

| Field | What it does |
| --- | --- |
| **Model** | The model asset. |
| **Faces forward** | Turns the model 180° so its front matches the object’s forward (−Z), which behaviors and *Look at* use. Untick it if a character walks backwards. |
| **Animation** | The animation clip to play (models with clips only), with **▶ preview** in the editor. *None (still)* = no animation. |
| **Play on start** | Loop the chosen clip from the start of the game. |
| **Animation speed** | 1 = normal, 2 = twice as fast. |
| **Far model** | A lighter version of the model (a low-poly model from Files) that takes over from far away. See [Distance and detail](#distance-and-detail). |
| **Switch distance** | Meters from the camera where the **Far model** takes over (default 30). Shown once a **Far model** is picked. |
| **Hide beyond** | Meters from the camera past which the model is not drawn at all. 0 = never. |
| *(one slider per blend shape)* | Only for models that have **morph targets**: see [Morph targets](#morph-targets). |

## Morph targets

Some models carry **morph targets** (also called blend shapes or shape keys): a face that smiles or blinks, a door that bends open, a balloon that inflates. If your model has them, the **Mesh** card shows a slider for each one, from 0 (as in the file) to 1 (fully bent). Set them in the editor to choose how the model starts.

While playing:

- Action **Set morph target**: the *Morph target* name (exactly as the slider is named), the value 0 to 1, and **Seconds** to blend over (0 = at once).
- Scripts: `entity.morphTargets` (the names), `entity.setMorph('Smile', 1, 0.3)` (name, value, seconds), `entity.getMorph('Smile')`.

A name the model doesn't have is reported in the console instead of silently doing nothing. If the model also plays an animation clip that moves the same morph target, the clip wins while it plays.

## Distance and detail

A model with many triangles is slow to draw, and from far away you can't see the detail anyway. Two settings on the **Mesh** card help:

- **Far model**: a second, lighter model. Past **Switch distance** the object shows it instead. It is the same object with the same color, material and size, only a cheaper mesh. Pick it in the same way as the **Model**.
- **Hide beyond**: past this distance the object is not drawn at all.

The camera's distance is checked a few times a second, and the switch has a little slack on both sides, so an object right at the distance does not flicker. The Far model is not animated and does not move the collider (the collider always follows the main model). An object with a Far model or a **Hide beyond** distance is drawn on its own, not grouped with copies (see [Performance](../help/performance)).

## Animations while playing

- The **Platformer**, **Top-down** and **Follow target** behaviors animate characters automatically (with *Animate* on): **idle** when standing, **walk** / **sprint** when moving, **jump** / **fall** in the air — using whichever of these clips the model has.
- Actions: **Play animation** (loop or once), **Stop animation**, **Set animation speed**. Condition: **On animation finished**, **Is playing animation**.
- Scripts: `entity.playAnimation('wave', false)`, `entity.getAnimationNames()`.
- For idle / walk / run / jump / attack with blends, layers and transitions, use an [Animator](./animator) instead.

## Ragdoll

A rigged character can go limp with physics, like a death animation that falls and tumbles where it stands. Use the **Ragdoll** action on the object (turn it on or off), or in a script `entity.ragdoll()` and `entity.ragdoll(false)`. The model must have a skeleton: the engine makes a loose body for each bone chain, joins them, and lets physics move the bones. The character keeps the speed it had.

- The object itself stays where it was; only its bones move.
- Turning it off brings the character back to its animation (and its physics body back) from where it lies.
- Joints are kept inside a range (how far a bone may swing and twist from the pose it had), so a knee or a neck does not fold any way it likes. The limbs don't bump each other, so it is still loose rather than realistic. Characters with clean bones for the body, arms and legs look best.

### Ragdoll component

Add a **Ragdoll** component to the object to tune it (without one every bone gets the defaults). **Fill from model** lists the bones that get a body; then open a bone to change:

- **Enabled** off: the bone gets no body and follows the bone above it (fingers, toes).
- **Swing** and **Twist**: how many degrees the bone may bend away from its starting pose, and turn about its own length.
- **Thickness**: the capsule's radius as a share of the bone's length (0 is automatic).
- **Shape**: **Capsule** or **Box**. Either one is fitted to the bone's own mesh, so the body encloses the model and a leg does not sink into the floor. Thickness 0 uses that fit; a number overrides it.

**Mass** is the whole body's weight in kg, shared out by size, though no bone gets less than a twentieth or more than a third of it (a feather-light hip joined to a heavy torso would spin like a top). With the object selected, the view draws a capsule along every bone that gets a body and a cross at each joint, and they follow an animation preview. A bone shown in red is not in this model any more: fill again after changing the model.

### Pushing a ragdoll

While the character is limp, `applyImpulse`, `applyForce`, `setVelocity` and `getVelocity` act on all its bodies together. For more control, in a script:

```ts
// Start limp with a shove (a hit that knocks it down)
entity.ragdoll(true, { impulse: { x: 0, y: 4, z: -8 } });

// Push one part: any bone whose name contains the text, in any case
entity.ragdollPush("head", 0, 0, -3);
entity.ragdollPush("arm", 2, 0, 0); // both arms

// Where the hips are now (null while it is not limp), for a camera or a pickup
const hips = entity.ragdollPosition;
```

The object itself never moves while it is limp, so use `ragdollPosition` to follow the body.

In an event sheet, the **Ragdoll** action has **Shove X/Y/Z** for the start, **Push ragdoll part** pushes the bones whose name contains the text, and the properties `hipsX`, `hipsY` and `hipsZ` (e.g. `Guy.hipsY`) give the hips, or the object's own position when it is not limp.

## Parts of a model

Every part of a model (a hand, a helmet, a wheel) is listed under the object in the Objects tab. You can hide a part, give it another material, or attach other objects to it. See [Model parts](../editor/objects#model-parts).

## Colliders for models

With **Collider → Automatic**, a model uses its real shape: exact triangles for objects that never move, convex parts for moving ones. See [Physics](./physics#collider-shapes).
